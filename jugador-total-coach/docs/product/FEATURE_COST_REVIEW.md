# Revisión antes de añadir una funcionalidad

Plantilla. No es una auditoría ya realizada.

## Propuesta
- Función y usuario beneficiado:
- Escenario de uso actual y crecimiento previsto:
- Necesidad dentro de la fase aprobada:
- Soluciones existentes que se reutilizan:

## Dependencias y derechos
Para cada dependencia, asset o servicio:
- Nombre, versión/hash, proveedor y fuente primaria:
- Fecha de revisión y documento/términos aplicables:
- Estado: propuesto / revisado / instalado / probado:
- Costo obligatorio inicial y recurrente:
- Límites: funciones, equipo, usuarios, ingresos, renders, minutos, almacenamiento:
- Uso comercial, automatización, modificación y distribución autorizados:
- Cuenta, conexión, telemetría o servidor necesarios:
- Restricciones de contenido, formato, codecs, plugins o plantillas:
- Obligaciones de atribución/avisos y compatibilidad con el producto:
- Disparadores que exigirían pagar o pedir permiso:
- Alternativa a costo cero y esfuerzo de sustitución, no supuesto como cero:

## Efecto sobre la aplicación
- Módulos que cambian:
- Datos que se conservan y formato exportable:
- Comportamiento si el proveedor falla o deja de cubrir el caso:
- Confirmación de que el entrenamiento local sigue disponible:
- Evidencia de rendimiento en el equipo objetivo:

## Decisión
Admisible / admisible condicionado / pendiente / bloqueado.

No convertir una estimación en evidencia. Ante una necesidad de pago, detener SOLO la integración afectada y presentar una alternativa, sin contratar ni degradar el núcleo local. Revisar cambios sustanciales de contexto, no solamente nuevas pantallas.
